# Kalshi retention — what it actually is. 2026-08-14.

Task packet 2, T4 Part A and T6. All measurement raw HTTP from the Kernel VM, explicit
User-Agent, status codes reported rather than booleans.

**The packet's challenge was correct.** The 2026-08-13 coverage note asserted a rolling
window from two observations — KXRAIN going 22 → 23 events, which is growth at the *front*,
and a single day's floor reading. The back edge was never measured. It has now been.

---

## The answer

**Market-level data is retained for a uniform, time-based window of 67 days. Event-level
metadata is retained for years.** These are different objects with different rules, and
conflating them is what made the earlier note's evidence weak.

### The back edge moves — measured, not inferred

The same series, same query, one day apart:

```
             2026-08-13    2026-08-14
KXHIGHNY     2026-06-07 →  2026-06-08
KXMLBGAME    2026-06-07 →  2026-06-08
```

**One day per day.** This is the observation the earlier note was missing. Two timepoints is
not ten, and the longitudinal census (T4 Part B) should still run, but the direction is no
longer an inference from front-edge growth.

## T6 — why KXRAIN's floor looked five weeks later

**Explanation 1, series age. Confirmed; the other two are excluded.**

`/events?series_ticker=KXRAIN&status=settled` returns **24 events in total, cursor exhausted,
earliest `KXRAIN-26AUG01`.** KXRAIN is a young series. Its floor at 2026-07-16 is where its
history *begins*, not where retention cut it. The same pattern holds for `KXWTI15M` and
`KXGOLD15M`, both flooring 2026-07-31 with `evList=899`, exhausted, first event `26AUG010000`.

The other late-flooring series are seasonal rather than retained differently — `KXNBAGAME`
(floor 06-09, newest 06-14), `KXNHLGAME` (06-10 / 06-15) and `KXTONYAWARDS` (06-08 / 06-08)
stopped producing events, so their newest is old too. `KXFED`, `KXPAYROLLS`, `KXCPIYOY` and
`KXEGGS` are low-frequency: two or three events inside 67 days, so the floor lands wherever
the third-most-recent print happened to fall.

- **Explanation 2, count-based retention: EXCLUDED.** See the table — floor date is flat
  against event frequency, not inversely related to it.
- **Explanation 3, pagination artifact: EXCLUDED for `/markets`.** Cursors exhausted on most
  series, and the identical floor across volumes from 25 to 6,348 events cannot be produced
  by enumeration stopping early. It **is** real for `/events`, which is why the two endpoints
  disagreed (below).

## The two endpoints genuinely differ, and it matters

| | reaches back to | governs |
|---|---|---|
| `/markets?series_ticker=…&status=settled` | **67 days** | market rows, `result`, prices, candlesticks |
| `/events?series_ticker=…&status=settled` | **years** — `HIGHNY-21AUG06`, `CPIYOY-22DEC`, `FED-21DEC` | event tickers and titles only |

Event metadata outliving market data is a trap: `/events` will happily list
`KXHIGHNY-25DEC15`, and `/markets?event_ticker=KXHIGHNY-25DEC15` then returns **zero rows**
under every status filter tried (`(none)`, `settled`, `closed`; `finalized` is a 400). The
event looks reachable and is not.

**Candlesticks expire with the market data**, which is the finding that matters most for study
design. Probed with a control:

```
KXHIGHNY-26JUN10-T82   200, 25 candles
KXHIGHNY-26JUN08-T82   404 not_found
KXHIGHNY-25DEC15-T82   404 not_found
CONTROL impossible     404 not_found
```

The strike may not exist on older events, so that probe alone is not decisive — but since
`/markets?event_ticker=` returns nothing for those events, no valid ticker can be obtained by
any route, which settles it. **There is no endpoint that escapes the 67-day floor.**

## What is now known, and what is still assumed

**Known.** Market-level retention is time-based, uniform across series, and currently 67 days
(floor 2026-06-08 on 2026-08-14). It advanced exactly one day between 08-13 and 08-14 on two
independently checked series. Event metadata is not subject to it. Candlesticks are. KXRAIN's
apparent anomaly is series age. Count-based retention and `/markets` pagination are excluded.

**Assumed.** That the one-day advance observed across a single 24-hour gap continues — two
timepoints establish direction, not a law. That 67 is stable rather than drifting. That no
authenticated endpoint reaches further (T5, untested — it needs credentials this project does
not have). The ten-day census in this directory exists to convert the first two assumptions
into measurements.
