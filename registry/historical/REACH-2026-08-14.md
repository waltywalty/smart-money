# A2 — How far back the Kalshi historical path actually reaches

**Date of measurement:** 2026-08-14 (UTC)
**Packet:** coworkpacket3autonomous, Phase A, task A2
**Instrument:** Kernel VM, raw `urllib` over HTTPS, explicit User-Agent
`smart-money-research/1.0`. No WebFetch. Status codes recorded, never booleans.
An impossible control key accompanies every probe class.

> **Dating note.** Three independent clocks — the Cowork host, the Kernel VM, and
> the `Date:` response header from `api.elections.kalshi.com` — all read
> **Fri, 14 Aug 2026**. The A1 deliverable committed earlier in this run is named
> `A1-FEE-ROUNDING-2026-08-15.md`; that filename is one day ahead of its own
> measurement date. The file is not renamed here (renaming a committed registry
> file mid-run is exactly the kind of unforced change the packet forbids). The
> discrepancy is parked as **P6**.

---

## What would overturn this

1. **The live-path floor moving.** Every claim below about `/markets` reach rests
   on a floor measured on one day. If the floor is a rolling window, the numbers
   here are a snapshot, not a constant. **This has not been measured over time.**
   The census scheduled task is the instrument that would settle it.
2. **`/historical/cutoff` advancing.** It read `2026-06-14T00:00:00Z` today and
   read the same value in earlier sessions of this project. If it is frozen
   rather than lagging, the overlap band described below is permanent; if it
   advances, the band moves and any collection keyed to today's boundary rots.
3. **A series whose `/events` floor is deeper than its `/historical/markets`
   floor.** None of the eight series tested showed this. One that did would
   invert the recommended collection order.

## A2.1 — Depth: how far back `/historical/markets` goes, per series

Paged `GET /historical/markets?series_ticker=&limit=1000` following `cursor` to
exhaustion. Rows counted in code, never self-reported.

| series | rows | events | pages | earliest close | latest close | HTTP |
|---|---:|---:|---:|---|---|---|
| KXHIGHNY   | 9004 | 1769 | 10 | 2021-08-07T03:59:00Z | 2026-06-14T04:59:00Z | 200 |
| KXHIGHCHI  | 9001 | 1757 | 10 | 2021-08-20T03:59:00Z | 2026-06-14T05:59:00Z | 200 |
| KXMLBGAME  | 6576 | 3288 |  7 | 2025-04-16T20:04:06Z | 2026-06-14T23:04:31Z | 200 |
| KXCPIYOY   |  582 |   43 |  1 | 2022-12-13T13:25:00Z | 2026-06-10T12:29:00Z | 200 |
| KXFED      |  380 |   38 |  1 | 2021-07-26T23:00:00Z | 2026-04-29T17:55:00Z | 200 |
| KXPAYROLLS |  336 |   39 |  1 | 2023-04-07T12:25:00Z | 2026-06-05T12:29:00Z | 200 |

**The limit is data, not pagination and not the API.** In all six cases the
cursor exhausted — the loop terminated because Kalshi returned an empty cursor,
not because it hit the page cap (25). The floors track each series' launch, and
the ceilings sit at or below the historical cutoff.

**Legacy tickers resolve under the modern series ticker.** Querying
`series_ticker=KXHIGHNY` returns markets named `HIGHNY-21AUG06-T86`; the same
holds for `CPIYOY-`, `FED-` and `PROLLS-`. A collector keyed on the ticker prefix
rather than the series parameter would silently drop the pre-rename era — which
is 2021-08 to roughly 2022-12 for the weather series, i.e. most of the depth.

**KXRAIN returns zero historical rows** (HTTP 200, 0 rows, cursor exhausted).
This is decision-relevant for H57 / **P4**: under either reading of its
`revive_if`, `/historical` supplies no additional KXRAIN events. Recorded, not
acted on.

## A2.2 — Completeness: live and historical disagree, and the mechanism is now measured

A2.2 asked for the 2026-06-07 → 06-11 sample to be re-derived from `/historical`
and said any disagreement is itself the finding. There is a disagreement.

Markets with `close_time` in 2026-06-07 → 2026-06-10 inclusive:

| series | live markets | hist markets | live events | hist events | only-live | only-hist |
|---|---:|---:|---:|---:|---:|---:|
| KXHIGHNY   |  18 |  24 |  3 |  4 | 0 |  1 |
| KXHIGHCHI  |  18 |  24 |  3 |  4 | 0 |  1 |
| KXCPIYOY   |  27 |  27 |  1 |  1 | 0 |  0 |
| KXPAYROLLS |   0 |   0 |  0 |  0 | 0 |  0 |
| KXFED      |   0 |   0 |  0 |  0 | 0 |  0 |
| KXMLBGAME  |  58 |  94 | 29 | 47 | 0 | 18 |
| **total**  | **121** | **169** | **36** | **56** | **0** | **20** |

`/historical` is a strict superset for this window: 56 events against 36, with
**zero** events reachable on the live path and not on historical. An earlier run
of the same comparison over a window one day wider gave 74 against 54 — the
absolute counts move with the window, the delta does not: **only-hist = 20,
only-live = 0 in both runs.**

### The mechanism — three independent endpoints, not three calls to one

The first-order reading ("the live path drops data") is right, but the reason
matters more than the fact, and the obvious explanation is wrong.

**Refuted: a status-vocabulary artifact.** The live query used
`status=settled`. Re-running it with **no status filter at all** returns exactly
the same counts (18 / 18 / 58 / 27). Every returned market carries
`status="finalized"`, not `"settled"` — so the filter was not excluding anything,
and removing it recovers nothing. The missing events are not hiding behind a
status term.

**Measured: the live `/markets` endpoint has a hard floor on `close_time`.**
Paged with no status filter over 2026-05-01 → 2026-07-01:

| series | live markets | live events | earliest close returned | close-dates absent |
|---|---:|---:|---|---|
| KXHIGHNY  | 138 |  23 | 2026-06-08 | 06-05, 06-06, 06-07 |
| KXMLBGAME | 588 | 294 | 2026-06-08 | 06-05, 06-06, 06-07 |

Two unrelated series — daily NYC temperature and MLB games — share the identical
floor to the day. Nothing closing before 2026-06-08 is on the live `/markets`
path, in either series, at any page.

**Cross-checked against two different endpoints, per the SKILL.md rule:**

- `GET /events/KXHIGHNY-26JUN06?with_nested_markets=true` → **HTTP 200**, full
  event metadata (title, `strike_date: 2026-06-07T03:59:00Z`, settlement source,
  `mutually_exclusive: true`) and `"markets": []`. The event shell survives on the
  live path; its market rows do not. Control: `/events/{impossible}` → **404**, so
  the 200 is real and the empty array is real.
- `GET /historical/markets?event_ticker=KXHIGHNY-26JUN06` → **HTTP 200, 6 markets**,
  `close_time 2026-06-07T04:59:00Z`. The data exists; only the live path has
  dropped it.
- `GET /series/{s}/markets/{t}/candlesticks` → **404** for the same tickers (A2.4).

### The resulting architecture

```
2021-07-26 ....................... 2026-06-08 ........ 2026-06-14 ........ now
|<------ /historical/markets only ------>|<- BOTH ->|<-- live /markets only -->|
                                          overlap band
                                          (~6 days wide today)
```

The two paths are not redundant and neither is complete. **The union is the
universe; the overlap band is the only place a cross-check is possible.** Any
collection design that reads one path and assumes the other agrees is wrong by
construction — and it was wrong in exactly that way when packet 2 counted 4,787
events for this window off the live path alone. **That figure is an undercount.**
It is not corrected here: correcting a recorded figure mid-run is forbidden. It is
parked as **P7**.

### An API asymmetry that will bite a collector

`/markets` honours `min_close_ts` / `max_close_ts`. **`/historical/markets` does
not** — it accepted both parameters with HTTP 200 and returned rows outside the
requested window in all six series tested. Every window filter against the
historical path must be applied client-side. This is measured, not inferred: the
check was `all(row in window)` over the raw response, and it was `False` for
historical and `True` for live.

## A2.3 — Field parity: the predicted risk did not materialise, and a different one did

A2.3 warned that a missing `fee_multiplier` on historical rows would silently
reintroduce the assume-1.0 error H60 already caught once. **It does not, and an
earlier note in this run saying otherwise was wrong.**

Method: take the **same ticker** on both paths inside the overlap band and diff
the key sets. Anything else compares two different objects.

| comparison | live fields | hist fields | only-live | only-hist |
|---|---:|---:|---:|---:|
| `KXHIGHNY-26JUN13-T94` | 45 | 45 | 0 | 0 |

**Parity is exact.** All 45 keys present on both sides, including `result`,
`settlement_ts`, `settlement_value_dollars`, `expiration_value`, `floor_strike`,
`strike_type`, `yes_bid_dollars`, `yes_ask_dollars`, `volume_fp`,
`open_interest_fp` and `last_price_dollars`.

**`fee_multiplier` and `fee_type` are absent from market rows on _both_ paths.**
They are **series**-level properties, and they are present and correct there:

| series | `fee_type` | `fee_multiplier` |
|---|---|---:|
| KXHIGHNY  | `quadratic`                  | 1 |
| KXFED     | `quadratic_with_maker_fees`  | 1 |
| KXMLBGAME | `quadratic_with_maker_fees`  | **0.5** |

Control: `/series/{impossible}` → 404. So the earlier framing — "absent from
historical" — was a comparison against an expectation, not against the live path.
Corrected here before it propagated. `KXMLBGAME` at **0.5** is a live instance of
the hazard SKILL.md records as "one series charged half of what the code
assumed"; any fee-model backtest must join the series row, on either path.

### The real parity defect: `open_interest_fp` is zeroed on the historical path

Across 41 markets in four events, all inside the overlap band, **exactly one
field disagrees, and it disagrees on every single market**:

| event | markets compared | differing fields | live `open_interest_fp` | hist `open_interest_fp` |
|---|---:|---|---:|---:|
| KXHIGHNY-26JUN13   |  6 | `open_interest_fp` |    48789.67 | 0.00 |
| KXHIGHCHI-26JUN13  |  6 | `open_interest_fp` |    22196.76 | 0.00 |
| KXMLBGAME-26JUN141607TBLAA | 2 | `open_interest_fp` | 1939544.19 | 0.00 |
| KXCPIYOY-26MAY     | 27 | `open_interest_fp` |      993.00 | 0.00 |
| **total**          | **41** | **1 field, 41/41 markets** | | |

**Which one is right is not established.** Two readings survive the evidence:
open interest legitimately goes to zero once positions settle, making the
historical value correct and the live value a stale high-water mark; or the
historical export drops the field to a default. Nothing measured here separates
them. What *is* established is that **a study reading open interest from the
historical path gets 0.00 for every market and no error**, and that a study
joining the two paths gets a discontinuity at the 2026-06-08 boundary. Recorded;
not resolved. Parked as **P8**.

**18 of 18 return candles on the historical path, back to 2021-07-26.**
Candlesticks reach as deep as market rows do; there is no separate, shallower
candle horizon. Where the two paths overlap they return **identical candle counts**
(33 / 33, 33 / 33, 75 / 75, 44 / 44) — a completeness gate that passes.

**4 of 18 return candles on the live path, and all four are overlap-band
markets.** The live candlestick floor is consistent with the live `/markets`
floor: `KXPAYROLLS-26MAY` closed 2026-06-05, below the floor, and 404s;
`KXCPIYOY-26MAY` closed 2026-06-10, above it, and returns 44.

Passing the **legacy** series ticker on the live path (`HIGHNY` instead of
`KXHIGHNY`, `FED` instead of `KXFED`, and so on) also returns 404. There is no
alias route back to the deep candles on the live path.

Control: `/historical/markets/KX-IMPOSSIBLE-CONTROL-19990101/candlesticks` →
**404**, so a 200-with-candles is a real read, and "absent" and "present but
empty" are distinguishable on this endpoint.

**Candle counts are small** — 12 to 33 hourly candles over an 8-day window on the
weather series. That is a statement about how thinly these markets traded, not
about retention, but it bounds what a depth study can do: **a missing quote means
nobody was trading**, which SKILL.md records as a selection variable, not a gap.

## A2.5 — Authentication

**Untested. Not equal.**

Every measurement in this document was taken **unauthenticated**. Whether an
authenticated session reaches further back, returns more rows per page, sees a
lower `/historical/cutoff`, or recovers `open_interest_fp` is **not known**, and
nothing here should be read as evidence that authenticated and unauthenticated
reach are the same. The endpoints that are authenticated by nature —
`/historical/fills`, `/historical/orders`, `/historical/positions` — were not
probed at all.

This is a gap in the instrument, recorded as a gap.

## Measured vs assumed — the explicit split

**Measured today, with status codes and controls:**

- `/historical/markets` floors and row counts for six series; cursor exhaustion in
  all six.
- Legacy ticker prefixes resolve under modern series tickers.
- KXRAIN: 200, zero rows.
- Live `/markets` `close_time` floor of 2026-06-08 in two unrelated series.
- The status-filter explanation for the live/historical gap is refuted.
- `/events/{e}` returns 200 with `markets: []` below the live floor; control 404s.
- `/historical/markets?event_ticker=` returns the same markets the live path lost.
- `/historical/markets` ignores `min_close_ts`/`max_close_ts`; `/markets` honours them.
- Field parity live vs historical: 45/45, zero either side.
- `open_interest_fp` = 0.00 on historical for 41/41 overlap-band markets.
- `fee_type` / `fee_multiplier` are series-level; KXMLBGAME is 0.5.
- Historical candlesticks: 18/18 return data back to 2021-07-26; overlap counts match exactly.
- `/historical/cutoff` = `2026-06-14T00:00:00Z`.

**Assumed, or believed but not measured:**

- That the live floor is *stable*. Measured once, on one day. It may be rolling.
- That the `2026-06-14` cutoff is *frozen* rather than lagging. It has read the
  same value across several sessions of this project, but no session recorded it
  as a time series until now.
- That the ~6-day overlap band is a designed property rather than a coincidence
  of today's boundaries.
- That the six probed series are representative of the ~500 on the exchange.
  Eight were touched in total; the other ~490 were not.
- That unauthenticated reach equals authenticated reach. **Untested.**
- Which of live or historical carries the *correct* `open_interest_fp`.

## What this licenses, and what it does not

**Licenses:** a bulk historical collection (B1) keyed on `series_ticker`, paging
`/historical/markets` to cursor exhaustion, filtering the window client-side,
joining `fee_type`/`fee_multiplier` from `/series/{ticker}`, and treating the
2026-06-08 → 2026-06-14 band as the cross-check region.

**Does not license:** any use of `open_interest_fp` from the historical path;
any claim that a live-path universe count is complete; any assumption that the
floor or the cutoff will hold tomorrow; any statement about authenticated reach.

**Parked by this document:** P6 (A1 filename date), P7 (packet 2's 4,787-event
universe count is an undercount), P8 (`open_interest_fp` disagreement).
