### What this says

1. **At the rate a checkpointed collector actually runs, there is no rejection.** Arms Q, B, C, E
   and the collection itself: **0 rejections in 550 requests** at 1.2 to 5.9 req/s, on both
   endpoints, *including immediately after a burst that was being rejected at 44%*. Packet 3's
   zero-in-19,483 is exactly what this regime produces. **Not instrument failure #11** - this
   run counted every response by code and logged retries separately, and the counters are zero.
2. **`docs/INFRA.md`'s 13%-at-3-threads-0.55s does not reproduce.** That configuration is 3.6
   req/s and returned 0 of 240. The rejection rate it describes belongs to a far higher request
   rate - 28 req/s measured 16.2%, which is near 13%. The observation was real; the parameters
   recorded beside it are not the parameters that produce it.
3. **Rejection begins near 11 req/s** (arm R: 0.8%) and is severe above 28 req/s.
4. **The limiter has memory, and it is not per-endpoint.**

### The finding I nearly published, and the arm that killed it

Arms F, G, H ran `/historical/markets` at up to 69 req/s with **0% rejection**. Arm I ran
`/markets` at 69 req/s seconds later and rejected **28.4%**. Same VM, same second, same
concurrency, same page size - only the endpoint differed. That is a clean-looking answer to
exactly the question T1.2 asked: *"If `/historical` really is rate-limited differently from
`/markets`, that is a documented infrastructure fact worth having."*

It is wrong. Arm L repeated arm H - identical configuration - and rejected **32.5%**. Arm P
repeated it again and rejected **44.1%**. `/historical/markets` is rate-limited; it simply had
not been pushed yet when H ran. The apparent endpoint asymmetry was **the order of the arms**.

Had the experiment stopped at arm I - which is where it would have stopped if the aim had been
to confirm a hypothesis rather than to break one - this document would state a false
infrastructure fact backed by a real, reproducible-looking measurement. The confound was
elapsed load history, and the only thing that exposed it was **repeating an arm after the
confound had changed.**

## Instrument facts established during this run

1. **`/historical/markets` reports `status: finalized`, never `settled`** - 100% of 2,000 rows
   sampled, `result` populated on 100%. Cross-checked on `GET /markets/{ticker}` and
   `GET /historical/markets/{ticker}`. A collector carrying `?status=settled` over from the live
   list would filter away every row and report an empty dataset as an honest zero.
2. **`result` is not binary.** `KXMLBGAME`: `no` 495, `yes` 495, **`scalar` 10** on one page.
3. **Rate limiting is shared across endpoints and has memory** - see above.
4. **The `series_ticker=` filter is honoured on `/markets`, `/historical/markets` and `/events`**,
   confirmed against the impossible control on all three in the same pass.
